# Аудит потока создания Дома для единого QR (LIVE01)

## 1) Что уже есть сегодня

- Публичный путь для создания делегации существует:
  - `GET /delegation/start`  
  - `POST /delegation/start`  
  (`app/routes/delegation.py`, строки ~145, ~154).
- Создание с привязкой к игре:
  - POST требует `game_code` и проверяет `Game(room_code)`.
  - Лидер вводит ник и размер команды.
- Режимы входа в дом реализованы:
  - `quiz` (вопросная логика + бонусная выдача)
  - `random` (случайный выбор дома)
- Рандомный выбор дома:
  - Для `entry_mode == random` используется `random.choice(available_houses)`.
- Ограничение уникальности дома:
  - Берутся уже занятые `house_key` из `House` этой игры;
  - из `HOUSE_CATALOG` отбрасываются занятые дома;
  - если свободных домов нет — создание блокируется.
- После создания:
  - создаётся `House` + лидер с ролью `lord_lady`;
  - формируется `invite_code`;
  - генерируется ссылка на лобби для присоединения:
    - `/delegation/join?game_code=<room_code>&invite_code=<invite_code>`;
  - готовятся QR-артефакты только для присоединения (`join_url_qr_*`).
- Присоединение новых игроков:
  - `GET /delegation/join` (форма)
  - `POST /delegation/join` проверяет code/house, лимит игроков, возвращает existing room при дубле ника.
- Роль для каждого игрока после входа назначается в лобби:
  - `GET /house/{invite_code}` и
  - `GET /house/{invite_code}/assign-role/{player_id}/{role_code}`.
- Защита уникальных ролей:
  - `diplomat`, `treasurer`, `maester`, `whisper_master` — уникальны в доме.
  - `house_sworn` может повторяться.

## 2) Что сейчас не подходит для «одного QR»

- `GET /delegation/start` сейчас не принимает и не использует query-параметры (`game_code`, режим и т.д.), хотя форма уже содержит поля и может их принимать, но данные приходят из `POST`.
- Для режима «blind draw» требуется поведение «+1 золото бонусом», но текущая серверная логика выставляет:
  - `resource_gold = 11` для `quiz`;
  - `resource_gold = 10` для `random`.
- Для самого стартового QR-кода нет server-side endpoint вида `/delegation/start-qr.*`, есть только QR для `/delegation/join`.
- В шаблоне `/delegation/start` для LIVE01 сейчас использован статический префилл кода (`value="LIVE01"`), что требует редактирования при смене комнаты.

## 3) Рекомендуемый one-QR flow (LIVE01)

1. Один QR указывает на единый вход:
   - ` /delegation/start?game_code=LIVE01&entry_mode=random `
2. Гость сканирует QR и попадает на форму создания дома.
3. Заполнить имя лидера и (при необходимости) подтвердить размер команды.
4. POST создаёт дом + лидера.
5. Экран результата показывает QR/ссылку приглашения, которой делёжится Дом (как сейчас для `/delegation/join`).
6. Другие игроки заходят по общей invite-ссылке/QR дома.
7. Лорд/леди после входа назначает роли на лобби /house/{invite_code}.

## 4) Manual pick vs blind draw (текущий и целевой)

- **Manual pick (quiz):**
  - Сейчас требует заполнить ответы/вопросы,
  - лидер получает +1 стартового золота относительно `random` (11).
- **Blind draw (random):**
  - Сейчас выбирает случайный дом из свободных,
  - лидер получает базу без +1 (+1 относительно random пока не даётся; старт 10).

## 5) +1 бонус: текущий статус

- **Текущий статус:** «случайный» режим не даёт бонус +1.
- Для требования «random = blind draw +1» нужен минимальный runtime патч (`resource_gold` для `random` или дополнительный бизнес флаг/override).

## 6) Лобби/приглашение

- По созданному дому уже есть готовая цепочка:
  - `join`-ссылка с `game_code` + `invite_code`;
  - QR-ссылки `/house/{invite_code}/join-qr.svg|png`;
  - страница лобби `/house/{invite_code}` и страницы игроков `/house/{invite_code}/player/{player_id}`.
- То есть текущая модель «создал дом -> раздал линк» уже работает.

## 7) Назначение ролей

- По умолчанию лидер входит как `lord_lady`.
- Остальные игроки заходят без роли (`role_id = None`).
- Назначение ролей выполняется лидером через лобби по ссылкам `/house/{invite_code}/assign-role/{player_id}/{role_code}` с уже существующей проверкой уникальности.

## 8) Риски и защита

- Риск неверного маршрута (непередаваемый `game_code`) — сейчас mitigates via hardcoded LIVE01 в форме.
- Риск изменения комнаты (LIVE01/другая) требует параметризации формы.
- Риск конфликтов ролей ограничен на уровне assign-маркеров.
- Риск повторного присоединения закрыт проверкой лимита команды и дублей ников.

## 9) Рекомендуемый минимальный runtime task

- **Аудит рекомендует runtime-патч (минимальный):**
  1. Поддержать query-параметры для `GET /delegation/start`:
     - `game_code`, `entry_mode`, `team_size_declared` (предзаполнение контекста).
  2. В `POST /delegation/start` добавить жёсткую валидацию параметров/хардкод на LIVE01 при одном QR.
  3. Привести `entry_mode` bonus policy под ожидаемую live-логику (если для blind draw обязателен +1 — исправить стартовое золото/флаги).
  4. Добавить выдачу QR для стартовой страницы (или стабильный печатный маршрут) по шаблону отдельного `start`-QR endpoint.

## 10) Можно ли уже сделать печатную QR-карту?

- **Сейчас:** можно распечатать QR на статической ссылке (например, `/delegation/start`) вручную (без runtime-эндпоинта для её автогенерации).
- **Для production-safe одного QR-карточного входа лучше добавить отдельный endpoint генерации start-QR**, чтобы картинка не зависела от внешнего сервиса.
