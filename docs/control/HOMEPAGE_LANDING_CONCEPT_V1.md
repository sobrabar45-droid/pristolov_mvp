# Homepage Landing Concept V1 for pristolov.ru

## 1. Purpose

The public homepage is needed because the root/start page must not feel empty or unexplained.

Главная страница должна сразу объяснять, куда попал человек и что делать дальше.

It should serve at least three audiences:

- player / participant;
- organizer / venue / partner;
- new visitor who opened the site for the first time.

The homepage must:

- explain what PRISTOLOV is;
- route people to the right next action;
- create the right visual and thematic first impression;
- support future franchise/business presentation;
- stay clear on mobile.

This is a concept document only. It is not a runtime implementation task.

## 2. Main homepage goals

- Stop being empty.
- Give a clear first impression in the first 5 seconds.
- Explain that PRISTOLOV is more than a quiz.
- Give players a clear entry path into the game.
- Give organizers/venues/partners a clear path to understand the format.
- Support future franchise interest without overwhelming players.
- Create trust: the project feels structured, live, and real.

## 3. Target audiences

### A. Player

Needs:

- understand what this is;
- know how to enter the game;
- not get lost;
- understand that the phone is part of a live event, not the whole game.

Likely question:

> "I got this link or scanned this QR. Where do I go?"

### B. Organizer / partner / venue

Needs:

- understand the format;
- understand business value;
- understand that this is a repeatable live event;
- see that there is a digital layer and future franchise/scaling logic.

Likely question:

> "Can this work in my venue or city?"

### C. New visitor

Needs:

- quickly understand the idea;
- see that the project is real and structured;
- decide whether to keep reading, join a game, or contact the team.

Likely question:

> "What is PRISTOLOV and why should I care?"

## 4. Recommended page structure

### Section 1. Hero / first screen

Include:

- project name: `PRISTOLOV`;
- strong tagline;
- atmospheric image/visual direction;
- short subtitle;
- primary CTA;
- secondary CTA.

Recommended hierarchy:

```text
PRISTOLOV
Живая командная игра Домов, интриг и решений

Не просто викторина: роли, золото, дипломатия, дуэли, Суд и финал в одном live-формате.

[Войти в игру]
[Для организаторов]
```

### Section 2. What is PRISTOLOV

Explain briefly:

- team-based House game;
- live event format;
- players have roles;
- role examples include Лорд / Леди, Дипломат, Мастер над золотом, Мастер над шёпотом, and Мейстер;
- Houses compete through questions, gold, influence, diplomacy, Harchevnya, duels, Court, and final decisions;
- digital support layer helps the host, screens, players, and cashier flow.

### Section 3. How the game works

Short 4-6 step explanation:

1. Players join a House.
2. Each player receives a role.
3. The host leads stages on TV/Master screens.
4. Houses answer questions, negotiate, spend gold, go on expeditions, and challenge each other.
5. Diplomacy and Суд shape public pressure.
6. One House reaches the strongest final position.

### Section 4. Why it is interesting

Explain player value:

- everyone has a role;
- team identity matters;
- strategy matters;
- negotiation matters;
- the game is more than questions only;
- players remember table drama, alliances, betrayals, duels, and final moments.

### Section 5. For venues / franchise / partners

Explain business-facing value:

- repeatable event format;
- strong audience involvement;
- supports teams, birthdays, corporate nights, bars, and themed events;
- digital layer helps scale operations;
- future franchise/scaling angle is possible;
- organisers, venues, and партнёры should see that this can become a repeatable event product;
- format can grow into city/operator model later.

Keep this section concise so it does not bury the player entry flow.

### Section 6. Entry/actions

Proposed actions:

- `Войти в игру`
- `Личный кабинет`
- `Для организаторов`
- `О формате`
- `О франшизе`
- optional `Связаться`

### Section 7. Footer

Basic contact/service area:

- project name;
- short description;
- contact method;
- partner/organizer link;
- legal/service links if needed later;
- note that game access may require a room code or event link.

## 5. CTA logic

This section describes future button logic only. It does not claim current runtime routes are already defined.

| CTA | Who clicks it | What they expect | Future target / flow | Current certainty |
| --- | --- | --- | --- | --- |
| `Войти в игру` | Player at event | Enter active game quickly | Room code / QR / event entry page | Concept-level until root flow is audited |
| `Личный кабинет` | Returning player, organizer, or operator | See personal/event area | Needs product decision: player-facing or organizer-facing | Concept-level only |
| `Для организаторов` | Venue, partner, event buyer | Understand format and contact | Organizer landing section/page with value, requirements, contacts | Concept-level only |
| `О франшизе` | City/operator/franchise prospect | Understand scaling model | Franchise/business presentation page | Concept-level only |
| `Связаться` | Visitor, partner, organizer | Contact team | Contact form, messenger link, email, or callback | Concept-level only |
| `О формате` | New visitor | Understand what the game is | Scroll to explanation or separate format page | Concept-level only |

Important implementation note:

If a runtime path is not confirmed, do not hardcode it in future implementation. Audit current routes first.

## 7. Visual direction

Visual direction only, no image generation in this task.

Mood:

- dark;
- noble;
- atmospheric;
- readable;
- dramatic but not overloaded.

References in words:

- Houses;
- intrigue;
- gold;
- banners;
- table strategy;
- live event energy;
- candle / hall / council feeling;
- modern digital layer under old-world ceremony.

Avoid:

- direct copyright-copy dependence;
- fantasy clutter;
- unreadable dark-on-dark text;
- tiny CTAs;
- huge lore blocks;
- generic quiz website look.

Design principles:

- mobile-first readability;
- big CTA buttons;
- clear contrast;
- short blocks;
- strong first screen;
- visual depth without noise.

## 8. Mobile-first notes

- First screen must work well on phone.
- `Войти в игру` must be visible immediately.
- Secondary CTA must not compete too aggressively with game entry.
- Text blocks must be short.
- No huge text walls.
- Franchise/partner info should not bury entry flow.
- Buttons should be thumb-friendly.
- Use section anchors or cards instead of long uninterrupted pages.
